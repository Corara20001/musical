# Musical P0/P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 制作手机竖屏可玩的合成声音交互演示，验证歌词 Tap、Hold、Trace 和声音响应，完成入口、结算和重试。

**Architecture:** TypeScript 模块隔离谱面、音频、渲染、触控、判定和结果。Canvas 按音频时钟绘制连续音高轨迹，Pointer Events 驱动判定，Web Audio 产生按操作开门的合成声音。

**Tech Stack:** Vite、TypeScript、Canvas 2D、Web Audio、Vitest。

**Spec:** `docs/superpowers/specs/2026-10-11-musical-v0-design.md`

## Global Constraints

- 手机竖屏优先，无后端、账号或游戏引擎。
- 时间从右向左滚动，音高越高位置越高，每半音保持可辨识间距。
- 所有时间窗口、音高容错、缩放与评分参数集中配置。
- 合成声音及原创短句必须标注为演示，不宣称完成 Satisfied 目标片段。
- 音频、谱面、渲染、触控、判定、结果独立；iPhone 真机验证状态如实报告。

## Review Focus

- pointercancel、松手和多指操作不会留下持续发声或重复计分。
- 切换后台停止发声，返回后需要主动继续，时钟不漂移。
- localStorage 失败不阻止完成结算和重试。
- 旋转和尺寸变化不会使音高判定与绘制错位。
- 快速重复 Play、Retry 不会启动重复音频或动画循环。

## Task 1: 谱面与判定核心

**Files:** `package.json`, `tsconfig.json`, `index.html`, `src/config.ts`, `src/chart.ts`, `src/judgement.ts`, `tests/judgement.test.ts`。

**Interfaces:** `VocalNote { id, startTime, duration, pitch, lyric, pitchCurve? }`；`pitchAt(note, elapsed): number`；`JudgementEngine.update(time, contacts): JudgementEvent[]`；`JudgementEngine.reset(): void`。Contact 包含 pointerId、开始时间、当前 MIDI 音高、按下状态。事件包含 noteId、grade、声音 gate 状态。

- [ ] 写失败测试：半音差保持精确；曲线中点线性插值；窗口外点击 Miss；同一音符只结算一次；提前松手不能 Perfect；trace 偏离后停止 gate；多指与取消可独立释放。
- [ ] 执行 `npm test -- --run` 确认测试因缺少实现失败。
- [ ] 实现可配置判定、连续音覆盖率、短暂偏离宽限及音符状态重置；建立原创短句演示 JSON 谱面，覆盖三类操作。
- [ ] 执行 `npm test -- --run`，核心测试全部通过。

## Task 2: 音频时钟和演奏响应

**Files:** `src/audio.ts`, `tests/audio.test.ts`。

**Interfaces:** `AudioEngine.start(): Promise<void>`、`time(): number`、`setVoice(noteId, pitch, enabled): void`、`pause(): void`、`resume(): Promise<void>`、`stop(): void`。伴奏由程序合成；人声音色为明确标注的合成演示音色。

- [ ] 写失败测试：暂停冻结时钟、重试归零、重复 start 不产生第二个 transport、stop 与 gate 关闭释放声部。使用注入的 AudioContext stub 校验生命周期。
- [ ] 执行 `npm test -- --run` 确认新增测试失败。
- [ ] 实现用户手势解锁音频、伴奏循环和按操作控制的带包络声部；音高曲线连续更新，无触摸时不播放对应声部。
- [ ] 执行 `npm test -- --run`，全部通过；实际浏览器试听点击、松手和持续滑动反馈。

## Task 3: 手机游戏与完整演示流程

**Files:** `src/rendering.ts`, `src/touch.ts`, `src/results.ts`, `src/main.ts`, `src/style.css`, `tests/results.test.ts`, `README.md`。

**Interfaces:** `Renderer.draw(time, noteStates, contacts): void`；`Renderer.pitchFromY(y): number`；`TouchInput.contacts(): Contact[]`；`TouchInput.clear(): void`；`saveBest(score): number`。main 负责 entry / playing / paused / results 状态切换。

- [ ] 写失败测试：存储不可用仍返回当前成绩、已有最佳成绩不降低、重试清空统计；尺寸变化后 pitchFromY 和绘制坐标互逆。
- [ ] 执行 `npm test -- --run` 确认新增测试失败。
- [ ] 实现入口的 Satisfied 原型标识和演示说明；画布绘制歌词、持续尾部、弯音、音高参考、固定演奏线、进度及反馈；同一按住动作自然覆盖 Hold 和 Trace。
- [ ] 实现 pointer capture、多指及取消清理，游戏区 touch-action 禁止滚动，尺寸变化更新映射；后台暂停并显示主动继续按钮。
- [ ] 实现结算字段、Retry / Back、本机 Best Score；集中管理单一动画循环，快速重复按钮不重复启动。
- [ ] 写 README：启动命令、参数位置、谱面格式、演示限制和未来人声/伴奏接入方式。
- [ ] 执行 `npm test -- --run` 和 `npm run build`，全部通过；浏览器检查约 390×844 和 375×667 竖屏，试玩 Tap/Hold/Trace、Miss、结算、重试、后台与恢复。真实 iPhone 未测试时明确记录。

## 交付边界

交付可运行 P0/P1 演示和后续素材接口。P2 原曲谱面、人声分轨及原曲准确性校对等待素材；本轮不把演示计为完整 V0。执行方式建议本会话直接实现，模块互相依赖且原型规模小。
