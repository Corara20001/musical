# Musical V0 实现设计（待确认）

## 目标与范围

以用户提供的 V0 产品规格为需求来源。手机竖屏优先，验证歌词作为音符、准确音高表达、Tap/Hold/Trace，以及操作对人声的直接影响。提供歌曲入口、试玩、结算、重试；不引入账号、后端或游戏引擎。

## 推荐实现

采用 Vite + TypeScript、Canvas 2D 和 Web Audio。相比 DOM 动画，Canvas 更适合连续音高轨迹和密集歌词；相比游戏引擎，依赖更少、模块更易修改。入口和结算采用普通 HTML。

时间从右向左滚动，演奏线固定在画面左侧约三分之一处。纵轴音高越高位置越高，每半音保持可辨识间距；音高范围、缩放、提前显示时间、纵向操作容错均可配置。歌词显示在音符起点，持续音用带状尾部表示，变音用连续曲线表示。操作捕获整个演奏区域，按时间和纵向距离匹配可操作音符，不要求精确点中字形。

## 模块与数据

- Audio：用户点击 Play 后解锁 AudioContext，以音频时钟驱动全局时间；伴奏持续播放，人声按成功操作开门或触发。持续音松手或偏离后淡出，避免爆音。前台恢复需要用户主动继续，避免时间与声音错位。
- Chart：独立 JSON，包含 id、startTime、duration、pitch、lyric、可选 pitchCurve 和 vocal 音频切片范围。曲线点以相对起点秒数及 MIDI 音高表示。
- Rendering：只读取时间、谱面及操作状态，绘制音高参考、歌词、持续轨迹和简短反馈。
- Touch：Pointer Events、多指独立跟踪、pointer capture、取消事件处理；游戏区禁用浏览器滚动手势。
- Judgement：时间窗口、纵向容错、持续音覆盖比例及 trace 采样均从配置读取。每个音符只结算一次；短暂偏离允许宽限。持续音在完成或失败后结算。
- Results：记录 Score、Max Combo、Perfect、Good、Miss；localStorage 保存 Best Score，存储不可用不阻止试玩。

## 音频与谱面依赖

当前工作区没有音频或谱面。准确完成指定 Satisfied 片段需要匹配的人声/伴奏素材及校对后的时间、音高数据。不能把合成音或猜测谱面标成 Angelica 原唱或准确原曲谱面。

若素材暂缺，先交付明确标注的 P0/P1 交互演示：使用原创短句、合成音高声音验证操作和开门反馈，保留原曲导入接口。该演示不能算完成 P2 或完整 V0 Definition of Done。取得素材后再制作并校对目标片段。

## 验证与完成标准

验证半音映射、时间匹配、连续音覆盖、trace 容错、多指及取消、重复结算防护、结算和重试重置。浏览器检查手机尺寸布局和实际音频响应。iPhone Safari 真机试玩仍需单独确认，桌面模拟不能代替真机结论。

实现顺序遵循 P0 → P1 → P2 → P3；未提供原曲素材时只完成演示范围并明确缺口。UI 仅做到歌词可读、轨迹可跟随、操作反馈清楚。
